# LocalMind

Локальный LLM-агент для работы с собственной базой знаний. Проект развивается в сторону системы с удобным CLI, индексацией файлов в PostgreSQL и запускаемым вручную дообучением моделей.


## Что уже есть

- Локальные модели и embeddings через Ollama.
- Агент на LangGraph с инструментом поиска по базе знаний.
- Хранение фрагментов и векторов в JSON, поиск по косинусному сходству.
- Индексация каталогов с UTF-8 документами `.txt` и `.md`: исключения, dry-run, отчёт и пропуск неизменившихся файлов.
- FastAPI backend и конфигурация через `config.toml` и переменные окружения.

Системные инструменты унаследованного прототипа отключены по умолчанию. Модули подтверждения действий пока не подключены к агенту.

## Быстрый старт

Нужны Python 3.11+ и установленная [Ollama](https://ollama.com/).

```bash
git clone https://github.com/g1nry/localmind.git
cd localmind
python3 -m venv .venv
source .venv/bin/activate
pip install -e '.[dev]'
```

Запустите Ollama и загрузите модели, указанные в `config.toml`:

```bash
ollama serve
```

В другом терминале:

```bash
ollama pull qwen2.5:7b
ollama pull nomic-embed-text
localmind
```

Backend будет доступен по адресу `http://127.0.0.1:8000`, документация API — `/docs`, проверка состояния — `/health`. Агент создаётся при первом чат-запросе, поэтому до него `agent_initialized` в `/health` равен `false`.

Без подкоманды `localmind` запускает сервер; `localmind index` индексирует каталог. Также доступен `python -m rag_agent`: внутреннее имя Python-пакета сохранено от исходного проекта.

```bash
curl http://127.0.0.1:8000/api/agent/chat \
  -H 'Content-Type: application/json' \
  -d '{"message": "Привет!"}'
```

`POST /api/v1/chat` — совместимый маршрут с тем же поведением. Агент сам выбирает, вызывать ли поиск. Индекс изначально пуст; наполнить его можно командой `localmind index`. HTTP-загрузка документов и автоматическое наблюдение за файлами пока не подключены.

## Индексация каталогов

Сначала проверьте план без записи в индекс и без запросов к Ollama:

```bash
localmind index ~/knowledge --dry-run
localmind index ~/knowledge --exclude '**/drafts/**' --dry-run --json
```

Затем выполните индексацию. Для неё нужна embedding-модель из конфигурации; chat-модель не запускается:

```bash
localmind index ~/knowledge
```

Можно описать источник в `config.toml`:

```toml
[sources.docs]
root = "./knowledge"
exclude = ["private/**", "**/drafts/**"]
```

Путь `root` разрешается относительно файла конфигурации, `~` разворачивается в домашний каталог. Источник выбирается по имени:

```bash
localmind index --source docs --dry-run
localmind index --source docs --json
```

Идентичность документа определяется корнем источника и относительным путём: одинаковые `notes.md` из разных папок или источников не перезаписывают друг друга. Исходники остаются на месте и не копируются в служебный каталог. В индексе сохраняются текст фрагментов, идентификаторы и параметры обработки. В выдаче поиска источник отображается как короткий ID источника и относительный путь.

Повторный запуск проверяет содержимое файлов и параметры разбиения/embedding-модели. Неизменившиеся документы пропускаются без вычисления embeddings. Для принудительного пересчёта используйте `--force`; он также нужен, если веса модели изменились при сохранении того же тега. При смене embedding-модели пересчитайте все источники и прочие документы индекса: смешивание разных векторных пространств пока не поддерживается.

Отчёт содержит состояния `added`, `updated`, `unchanged`, `skipped`, `failed`. В `--dry-run` первые два обозначают планируемые действия, а `chunks` для них равен нулю: embeddings не вычисляются. JSON-вывод включает список файлов, ID источника и сводку `counts`. Код завершения `1` означает ошибку, в том числе частичную; ошибочный набор аргументов возвращает `2`. Успех возвращает `0`.

Исключения используют маски `fnmatch` относительно корня, с поддержкой начального `**/` для совпадения и в корне. В отличие от shell glob, `*` может совпадать с `/`. Исключённые каталоги не обходятся. Всегда пропускаются `.git`, `.venv`, `__pycache__`, `node_modules`, `.env`, `.env.*`, symlink внутри источника и служебные каталоги документов/индекса LocalMind. Служебный каталог нельзя выбрать корнем источника.

Сейчас поддерживаются UTF-8 TXT/Markdown; лимит файла задаёт `documents.max_upload_size_bytes` (по умолчанию 1 МиБ). Ошибки кодировки, чтения и провайдера попадают в отчёт; другие файлы продолжают обрабатываться. Новые фрагменты документа заменяют прежние только после успешной подготовки всех embeddings. При сбое сохраняется старая версия в индексе.

Удаление или исключение файла не удаляет его прежние записи из индекса. Перенос корня создаёт другой источник, старые записи также сохраняются. Очистка и watcher будут отдельным этапом; текущий JSON-индекс предполагает один процесс записи одновременно.

## Программный поиск без chat-модели

Сервисы создаются явно и закрывают HTTP-клиенты при выходе из контекста. Импорт модулей не открывает соединения и не создаёт индекс. Для поиска нужна только embedding-модель; генерация и агент не запускаются. Пустой индекс возвращает пустую выдачу без обращения к Ollama.

```python
import asyncio

from rag_agent.bootstrap import open_services


async def main():
    async with open_services() as services:
        result = await services.retrieval.retrieve_context("Что описано в документах?", top_k=3)
        for context in result.contexts:
            print(context.source, context.text)


asyncio.run(main())
```

Для отдельного приложения или теста можно передать `Settings` в `open_services(settings)` или создать HTTP-приложение через `create_app(settings)` из `rag_agent.main`. Состояние и инструменты каждого экземпляра изолированы. Chat-клиент подключается к указанному адресу Ollama напрямую, без proxy-настроек окружения; его пулы соединений принадлежат контексту сервисов. Прежние глобальные экземпляры `retrieval_service`, `red_team_agent` и `tool_registry` заменены явным созданием сервисов; примеры в `examples/` обновлены.

Оба HTTP-маршрута чата сохраняют формат успешного ответа `answer`/`contexts`. Ошибка выполнения агента теперь возвращает HTTP 502 с полем `detail`, а не успешный ответ с текстом ошибки.

## Конфигурация

Основные параметры находятся в `config.toml`:

```toml
[ollama]
base_url = "http://localhost:11434"
chat_model = "qwen2.5:7b"
embedding_model = "nomic-embed-text"
timeout = 120.0
```

Файл конфигурации можно выбрать через `RAG_AGENT_CONFIG`. Переменные окружения имеют приоритет над TOML: например, `OLLAMA_CHAT_MODEL`, `OLLAMA_BASE_URL`, `APP_PORT`, `DOCUMENTS_DIR`, `INDEX_PATH`.

Документы и индекс сохраняются в `data/` и не попадают в Git. При смене embedding-модели индекс нужно построить заново.

## Разработка

```bash
pip install -e '.[dev]'
make test
make run
```

Тесты используют подставные embeddings и не требуют запущенной Ollama. GitHub Actions проверяет тесты и сборку Python-пакета на Python 3.11 и 3.13.

```text
src/rag_agent/   агент, API, конфигурация, индексация и хранилище
config.toml     настройки локального запуска
data/           локальные документы и индекс
examples/       ручные сценарии исходного прототипа
tests/          автоматические тесты
```

Для запуска backend в контейнере:

```bash
docker compose up --build
```

Ollama запускается отдельно на хосте. Порт контейнера опубликован только на `127.0.0.1`.

## Ограничения прототипа

История диалога между запросами пока не сохраняется: `thread_id` возвращается агентом как идентификатор, но не связан с постоянным хранилищем. Параметры `use_rag` и `top_k` в chat API пока не управляют поиском; поле `contexts` в ответе остаётся пустым. Индекс JSON рассчитан на небольшие локальные эксперименты.
